# /housing/ 可行性调查：东京各区房价地图（2026-10-22）

调查方式：仓内接入点测绘（scout）+ 数据源/许可/口径/先例并行调研（workpool）+ 对抗核验（verify 池，逐条尝试推翻）+ 本地实测（真实 CSV 与地価公示 GeoJSON 落盘统计）。

结论：**可以做，数据是真的、许可够用、模板能复用；但"平均价格"要改成"中位数"，且必须接受一条新的季度数据管线与全站命题改写（三尺度 → 四尺度）。**

## 3. 口径设计（"平均价格"要改）

### 3.1 推荐口径

| 项 | 取值 | 理由 |
|---|---|---|
| 代表值 | **中位数** | 分布右偏；都心均值比中位高 34–58% |
| 队列 | 中古マンション等 · 60–80㎡ · 成約価格 | 字段够、n 最大、可比性最高 |
| 地图色 | ㎡単価中位（円/㎡，log 分档） | 面积归一化，跨区可比 |
| 卡片主数字 | 70㎡換算（= ㎡単価中位 × 70） | 用户直觉"这套多少钱" |
| 次数字 | 総額中位 + 平均 + n | 满足"看平均"的需求，同时暴露偏差 |
| 时间窗 | 最近 4 个季度滚动（当前 2025Q2–2026Q1） | 单季噪声大；4 季合并后每区 n≥347 |
| 样本阈值 | n≥30 上色；n<30 灰块标"样本不足" | UK HPI 同款纪律（成交量过低不发布） |
| 色阶 | log 值分位 6 档，单强调色透明度阶梯 | 港 200万 vs 足立 56.7万 円/㎡ = 3.5 倍，线性会把 20 个区压成一档 |

### 3.2 可选图层（v1.1）

- 取引価格（2005Q3 起，可做 20 年趋势；但口径是申报价，需与成約分开标注）。
- 地価公示点（2,560 点，按 円/㎡ 上色）——明确写"土地・標準地"。

### 3.3 文案纪律

- 不写"该区平均房价"，写"中古マンション 60–80㎡ 成約価格の中央値（70㎡換算）"。
- 页面固定显示数据基准（`データ基準：2026年第1四半期`）与更新日期。
- 不写"官方地价/官方房价"，避免冒充政府出品（PDL §1.1.2）。

## 5. 必须先拍板的产品决策：全站命题

第 4 章不是"加一张卡"，是改命题。仓内"三"的硬编码 12 处：

- `cover.title`「日本を、三つの尺度で見る」、`cover.lede`「three kinds of time」、`cover.cta`「三つの章へ」、`cover.section.eyebrow`「THREE SCALES / 三つの章」、`cover.section.h`「同じ国土を、三つの時間で」、`nf.p`「三つの章から辿り直せる」
- 首页 `<title>`/description「…三つの入口から直接起動する」、`aria-label="Three scales"`、`hp-band` 的 `repeat(3)` 三连幅
- `llms.txt`「日本を三つの尺度で見る…」、README/design-lock/SPEC 的页数表述

三条路线（择一）：

1. **四尺度**：「日本を、四つの尺度で見る」。改动最小，但"尺度"叙事从"时间/空间"扩到价格会略牵强。
2. **换命题**：从"三つの尺度"改为"三つの時間 + 一つの値段"之类；首页改 2×2 网格。
3. **不加章**：把房价做成犯罪页里的一个叠加图层（治安 × 房价），保住"三尺度"。差异化最强，但用户要的"第四个栏目"就不成立。

## 6. 风险表

| 风险 | 影响 | 对策 |
|---|---|---|
| API key 审批不确定/被拒 | 无法自动更新 | 先用手动 CSV 快照上线；申请时用"个人"种别、写明公开数据站用途 |
| 取引価格是申报口径、非全量 | 与中介口径有差 | 默认成約価格；页面标注"成約＝REINS 成約報告" |
| 组成偏差（面积/筑年/站距） | 区际不可比 | 固定 60–80㎡ 带 + 中位数 + 显示 n |
| 千代田等小样本 | 数值抖动 | n≥30 上色；60–80㎡ 带 n<100 的区标"参考" |
| 数据滞后 4 个月 | 用户以为最新 | 页面固定显示 `データ基準：2026Q1` + 取得日 |
| 成約価格源自 REINS 二次加工 | 第三方权利残余风险 | 国交省已标"商用〇"且不可识别化；保守版可只用取引価格 |
| 字体子集膨胀 | 全站 FONT_VER 变更、缓存失效 | 只新增区名与固定文案，控制在 50 字内 |
